# NXSG platform and integration research

**Research date:** 2026-09-17  
**Scope:** NXSG’s proposed Unity Built-In/HLSL backend for VRChat avatar creators.  
**Evidence labels:** **Verified** means stated by a primary source; **Recommendation** is an NXSG design choice based on those facts; **Spike** is an implementation question that must be tested.

## Executive findings

The safe first target is a Linux-authored VRChat Unity 2022.3 project using the Built-In Render Pipeline, with the VRChat SDK pinned to a tested 3.10.x line. As of this research date, VRChat documents Unity **2022.3.22f1** as its current supported editor and the latest release page lists SDK **3.10.5**, released 2026-09-04. VRChat explicitly warns that moving to another Unity version causes uploaded content not to load. Linux authoring and Linux editor milestones do not require a Windows machine. Keep the authoring OS separate from the PC client’s ShaderLab/HLSL/DX11 contract; native Windows portability is a future smoke claim. ([current Unity version](https://creators.vrchat.com/sdk/upgrade/current-unity-version/), [SDK 3.10.5](https://creators.vrchat.com/releases/release-3-10-5/))

VRChat avatar shader support is asymmetric. On PC, custom Built-In shaders are a reasonable supported product target, subject to VRChat’s fallback/safety behavior and normal Unity shader correctness. On Android/Quest avatars, VRChat says only shaders supplied by the latest SDK are permitted; iOS shares the mobile constraints and is still documented as beta. A custom shader can be technically compilable for a mobile GPU and still be disallowed for avatar upload or replaced at runtime. NXSG should therefore produce a PC shader and a separate mobile plan: use VRChat Mobile shaders/materials or a deliberately reduced platform override, with a hard validation error when a graph requires an unsupported mobile feature. ([Android/Quest shader limits](https://creators.vrchat.com/platforms/android/quest-content-limitations/), [cross-platform setup](https://creators.vrchat.com/platforms/android/cross-platform-setup/), [iOS setup](https://creators.vrchat.com/platforms/iOS/setting-up-unity-for-creating-ios-content/))

The generated Built-In shader needs a conventional ShaderLab contract: correct SubShader tags and queues, a `ForwardBase` lighting pass (and only the needed `ForwardAdd` behavior), a `ShadowCaster` pass when casting shadows, mobile-safe variants where applicable, stereo instancing macros, and a declared fallback. Exposed values must remain ordinary named material properties so Unity animation and VRCFury can target them. Static compile switches belong to genuinely fixed build choices; animated values must be properties, not keywords. ([Unity pass tags](https://docs.unity3d.com/2018.3/Documentation/Manual/SL-PassTags.html), [Built-In render paths](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-RenderPipeline.html), [stereo instancing](https://docs.unity3d.com/2022.3/Documentation/Manual/SinglePassInstancing.html), [fallback](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-Fallback.html))

## 1. Unity, SDK, and project pinning

**Verified.** VRChat’s current editor page names Unity 2022.3.22f1 and says the Creator Companion is the simplest installation route. It specifically says upgrading away from that version can make uploaded content fail to load. Android and iOS Build Support modules are optional at installation time but required for those targets. VRChat’s getting-started docs say VCC creates Unity 2022.3.22f1 projects and installs the SDK; the SDK 3.4.2-or-earlier note refers to the old Unity 2019 line. ([current version](https://creators.vrchat.com/sdk/upgrade/current-unity-version/), [getting started](https://creators.vrchat.com/getting-started/))

**Verified.** VRChat’s release index lists 3.10.5 as the latest release found during this research, dated 2026-09-04. The 3.10.5 release adds Toon Standard AudioLink support, including mobile, and documents SDK version defines. NXSG should test against the exact SDK package set used by its CI fixture rather than only trusting a broad `3.10.x` label. ([release index](https://creators.vrchat.com/releases/), [3.10.5 release](https://creators.vrchat.com/releases/release-3-10-5/))

**Recommendation.** Treat the editor, Base SDK, Avatars SDK, and optional integrations as a compatibility tuple. Record it in NXSG’s diagnostic report and package CI matrix. Fail early with “project editor is not the tested VRChat editor” rather than generating a result with unknown upload behavior. Use VRChat’s UPM/VPM version defines for optional code paths; the SDK docs describe version defines as the preferred detection method and call the legacy `VRC_SDK_VRCSDK3` symbols deprecated. ([SDK detection](https://creators.vrchat.com/sdk/detecting-vrcsdk/))

**Spike.** The official VPM listing currently exposes Base and Avatars 3.10.5 entries, with Avatars requiring Base exactly 3.10.5; it reports zip SHA256 values `fbfb3e7a38778dcb55d7a860286819e6f0726d10d5039f61474bd1b9c629029e` (Base) and `03bdea0c24257070f0e7a73c9033742a1ce0f67463b12a6c2ad29608b1f33a77` (Avatars). A fresh install and upgrade project still need to be exercised in Unity; the listing alone does not prove package import or upload behavior. The public listing can expose prerelease versions, and VCC allows selecting older releases; this is useful for a reproducible compatibility matrix but should not become an accidental downgrade path. ([official VPM listing](https://vrchat.github.io/packages/index.json))

## 2. Built-In shader contract: lighting, stereo, shadows, mirrors, fallback

**Verified.** Unity’s Built-In pipeline selects shader passes through `LightMode`. `ForwardBase` handles ambient, lightmap, the main directional light, and vertex/SH lights; `ForwardAdd` handles additional per-pixel lights; `ShadowCaster` writes object depth to a shadow map/depth texture. A shader with no forward-compatible pass falls back to another rendering behavior, so NXSG must emit deliberate passes rather than relying on incidental defaults. ([pass tags](https://docs.unity3d.com/2018.3/Documentation/Manual/SL-PassTags.html), [render pipeline](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-RenderPipeline.html))

**Verified.** Unity’s `Fallback` block selects a named shader when no compatible SubShader is found; `Fallback Off` produces the error shader. VRChat separately uses a `VRCFallback` SubShader tag when a user’s safety settings block a shader. VRChat documents tags including `Unlit`, `Toon`, `Cutout`, `Transparent`, `MobileToon`, `Hidden`, `toonstandard`, and `toonstandardoutline`; unknown tags fall back to Standard. The special Toon Standard tags copy same-named properties and target the VRChat Mobile Toon Standard fallback. ([Unity fallback](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-Fallback.html), [VRChat shader fallback system](https://creators.vrchat.com/avatars/shader-fallback-system/))

**Recommendation.** Every NXSG material should declare an explicit `VRCFallback` based on its appearance and provide a graph report showing what a blocked viewer sees. For toon output, `toonstandard` is a useful deliberate PC/mobile fallback candidate; a graph using transparency, fur shells, or custom vertex deformation must warn that fallback appearance may be materially different. Preserve `_MainTex`, `_Color`, and other copied names only when the graph actually supports their semantics; do not claim full property preservation automatically.

**Verified.** Unity’s custom-shader stereo guidance requires `UNITY_VERTEX_INPUT_INSTANCE_ID` in vertex input, `UNITY_VERTEX_OUTPUT_STEREO` in output, setup/initialization macros in the vertex function, and stereo setup in the fragment function. VRChat’s shader globals expose documented mirror and camera modes such as `_VRChatMirrorMode`, `_VRChatFaceMirrorMode`, and `_VRChatCameraMode`; VRChat warns that undocumented `_VRChat` names are a protected namespace. ([single-pass instancing](https://docs.unity3d.com/2022.3/Documentation/Manual/SinglePassInstancing.html), [VRChat shader globals](https://creators.vrchat.com/worlds/udon/vrc-graphics/vrchat-shader-globals/))

**Recommendation.** Make stereo and GPU-instancing support part of the backend template, not optional node logic. Test left/right eye parity, mirror mode, handheld camera mode, and screenshot mode. For fur or vertex animation, test bounds and shadow caster deformation together: an attractive main pass with stale shadow/bounds behavior is not a finished avatar shader. Keep mirror-specific behavior opt-in because mirrors are a scene cost; VRChat’s mirror documentation says mirrors can drastically reduce frame rate and recommends limiting layers and resolution. ([mirror component](https://creators.vrchat.com/worlds/components/vrc_mirrorreflection/))

**Verified.** Unity supports custom GPU-instanced shaders in Built-In, but a hand-written vertex/fragment shader needs instancing variants and macros. VRChat’s mobile shader page tells creators to enable GPU Instancing on materials. Unity also documents that `shader_feature` allows unused variants to be stripped, while `multi_compile` retains combinations; variant counts multiply across keyword lines. ([GPU instancing](https://docs.unity3d.com/2023.1/Documentation/Manual/gpu-instancing-shader.html), [VRChat mobile limitations](https://creators.vrchat.com/platforms/android/quest-content-limitations/), [variant stripping](https://docs.unity3d.com/2022.3/Documentation/Manual/shader-variant-stripping.html))

## 3. PC, Android/Quest, and iOS: policy versus capability

**Verified.** Android/Quest avatars may use only shaders provided with the latest SDK, under `VRChat/Mobile`. The documented list includes Toon Standard, Toon Lit, particle shaders, and world-only shaders. VRChat says the list can change. Toon Standard’s outline variant is PC-only; mobile automatically falls back to the non-outline variant. The Android optimization guide repeats that avatar shaders are restricted while world shaders are not. ([limitations](https://creators.vrchat.com/platforms/android/quest-content-limitations/), [optimization](https://creators.vrchat.com/platforms/android/quest-content-optimization/))

**Verified.** VRChat supports Windows, Android devices including Quest/PICO/Vive XR Elite and Android 10+ phones/tablets, and iOS 17+ iPhones/iPads. Cross-platform content is uploaded per build target, and per-platform avatar overrides can supply a reduced Android version under the same avatar ID. iOS fallback behavior is still described as experimental; an explicit iOS upload is recommended. ([platforms](https://creators.vrchat.com/platforms/), [cross-platform setup](https://creators.vrchat.com/platforms/android/cross-platform-setup/), [per-platform overrides](https://creators.vrchat.com/avatars/per-platform-avatar-overrides/))

**Recommendation.** NXSG should model three validation states: PC Built-In custom shader; mobile avatar graph constrained to a VRChat Mobile shader/material contract; and unsupported target. “Compiles for GLES/Metal” is only a technical capability check. “Allowed in a VRChat mobile avatar” is a platform policy check and must be implemented separately. For a graph with unsupported mobile features, offer a reduced generated material or an explicit per-platform override plan; never silently upload the PC shader as Android/iOS content.

## 4. VPM/VCC packaging and dependency strategy

**Verified.** VCC’s VPM format is compatible with Unity Package Manager and adds `vpmDependencies`, a direct package `url`, migration fields for legacy folders/files/packages, and optional `zipSHA256`. VCC recommends SPDX license metadata and documents `vpmDependencies` ranges such as `3.5.x` as `>=3.5.0 <3.6.0`. VRChat’s Public SDK API is intended to remain stable across non-breaking “Bump” releases. ([VPM packages](https://vcc.docs.vrchat.com/vpm/packages/))

**Recommendation.** Ship NXSG as a VPM package with editor assemblies, runtime generated-shader support only where necessary, samples, changelog, license, and clear Unity minimum `2022.3`. Keep AudioLink and VRCFury optional: NXSG’s core compiler must install and build without them. Use assembly definition version defines for `com.vrchat.avatars`; compile optional adapters only when the dependency exists. Publish immutable versioned zips with checksums and retain old releases, as VCC warns that deleting old package versions breaks projects using source control. ([package listings](https://vcc.docs.vrchat.com/guides/create-listing/), [community repositories](https://vcc.docs.vrchat.com/guides/community-repositories/))

**Install/upgrade gate.** Test adding NXSG through a local VPM listing, a remote listing, and a clean VCC avatar project. Upgrade from the previous NXSG package while preserving `.nxsg` graphs and generated assets. Open a project with no VRC SDK and verify the package remains usable for graph editing but marks VRChat build commands unavailable. Open with a supported SDK and verify package resolution, asmdef symbols, and generated shader import without console errors.

## 5. VRCFury and clean material animation

**Verified.** VRCFury’s public Actions page has a Material Property action that animates a property on a selected renderer, optionally all renderers. It says to mark a property animated when a shader supports locking, and warns Unity applies a material-property animation across every material on a renderer. This is the practical public contract NXSG should target: stable property names and ordinary animatable types, not private VRCFury implementation details. ([VRCFury Actions](https://vrcfury.com/actions/))

**Verified.** VRCFury’s addon API documents a preprocessor hook before VRCFury, temporary generated assets, and the `com.vrcfury.api` assembly reference. It explicitly says not to edit the user’s avatar descriptor assets directly and recommends using public merging logic. A current open pull request proposes adding `AddMaterialProperty` to the public API, which is evidence that deeper material-action automation is not yet a stable assumption. ([VRCFury API](https://vrcfury.com/api/), [AddMaterialProperty proposal](https://github.com/VRCFury/VRCFury/pull/347))

**Recommendation.** NXSG’s default integration is zero VRCFury code: generate clean properties, provide a right-click “copy property name” path, and document how to use VRCFury Material Property actions. If NXSG later adds an adapter, compile it conditionally against a tested VRCFury public API version and create temporary controller/assets through documented hooks. Do not reflect private classes or rely on an unreleased PR.

Avoid shader “locking” as a requirement for ordinary animated values. A property such as `_NXSG_EmissionPulse` should be a float/color/vector with a stable reference name and a default value. A shader keyword or static switch is appropriate only when the value is fixed for the built material, such as selecting a fur technique or removing an entire pass. If a creator needs to animate that choice, NXSG must either compile a dynamic branch/property path or explain that rebuilding is required. Keep shader keywords minimal; VRChat warns excessive keywords and unused material keywords can cause performance and rendering problems. ([VRChat optimization](https://creators.vrchat.com/avatars/avatar-optimizing-tips/), [Unity variants](https://docs.unity3d.com/2022.3/Documentation/Manual/shader-variant-stripping.html))

## 6. AudioLink contract and absent-data behavior

**Verified.** AudioLink is a community package that exposes a 128x64 RGBA audio texture to shaders and Udon. Its docs recommend including `Packages/com.llealloo.audiolink/Runtime/Shaders/AudioLink.cginc`, provide `AudioLinkIsAvailable()` and `AudioLinkGetVersion()`, and support direct shader use on avatars/worlds. AudioLink’s current repository `master` package manifest (read-only GitHub API, 2026-09-17) reports package version **3.1.2**, Unity **2022.3**, at commit `4aeb39503ce94cb250ed7570ee585e1be9cdb3aa` (2026-07-17). ([shader API](https://github.com/llealloo/audiolink/blob/master/Docs/README.md), [package manifest at pinned commit](https://github.com/llealloo/audiolink/blob/4aeb39503ce94cb250ed7570ee585e1be9cdb3aa/Packages/com.llealloo.audiolink/package.json))

**Verified.** AudioLink only produces meaningful reactive data when the world uses its community prefab. VRChat SDK 3.10.5’s Toon Standard integration documents fixed-rhythm Fallback Mode for worlds without AudioLink and supports Pulse, Scroll, and Bar effects, including mobile. AudioLink’s docs warn that CPU readback is expensive on Quest because asynchronous readback is unavailable; shader sampling is the safer path. ([VRChat 3.10.5](https://creators.vrchat.com/releases/release-3-10-5/), [AudioLink docs](https://github.com/llealloo/audiolink/blob/master/Docs/README.md))

**License.** The AudioLink repository’s current `LICENSE` at pinned commit `4aeb39503ce94cb250ed7570ee585e1be9cdb3aa` grants broad copy/modify/distribute rights with attribution notice and says the code may be used in CC 3.0+ projects; bundled scene assets have separate CC BY-NC-ND 4.0 and CC BY-NC 4.0 notices. NXSG should depend on AudioLink rather than copying its package, and should preserve third-party notices if samples or code are redistributed. ([license at current pin](https://github.com/llealloo/audiolink/blob/4aeb39503ce94cb250ed7570ee585e1be9cdb3aa/LICENSE), [VRChat attribution](https://hello.vrchat.com/legal/attribution))

**Recommendation.** AudioLink is an optional graph input with three explicit states: available and sampled; absent at runtime, returning a neutral value; and incompatible/unknown version, producing a build warning. Default absent-data behavior should be deterministic and attractive (zero amplitude or a user-selected fixed pulse), with no null texture sampling or black-emission surprise. Include a compatibility node version and preserve the fallback path in generated shader code. Do not add Udon GPU readback to avatars.

## 7. Required gates before implementation claims

1. **Compiler contract:** golden `Texture -> Toon -> Output` emits deterministic ShaderLab with `ForwardBase`, optional `ForwardAdd`, `ShadowCaster`, explicit queue/render type, `VRCFallback`, stereo macros, instancing support, and no unused keywords.
2. **Editor import:** clean Unity 2022.3.22f1 VCC avatar project; package install, domain reload, graph edit, material generation, close/reopen, and graph migration all pass with no errors.
3. **PC rendering:** Build & Test a representative avatar in desktop and VR; verify left/right eye parity, mirrors, shadows, camera modes, animation of every exposed property, and blocked-shader fallback.
4. **Mobile policy:** Build Android/Quest and iOS fixtures. Confirm unsupported custom avatar shaders are blocked by NXSG before SDK upload; confirm a Toon Standard reduced output passes SDK validation. Use Android USB Build & Test and iOS VTP Build & Test where hardware is available. ([Android Build & Test](https://creators.vrchat.com/platforms/android/build-test-mobile/), [iOS Build & Test](https://creators.vrchat.com/platforms/iOS/build-test-mobile/))
5. **VRCFury:** With the public Material Property action, animate float/color/vector properties on one renderer and multiple materials; verify the documented renderer-wide limitation and defaults. Test any adapter only against a pinned VRCFury package and public API.
6. **AudioLink:** Run the same material in an AudioLink world, a world without the prefab, and mobile. Verify `AudioLinkIsAvailable()`/version gating, fixed or neutral fallback, no CPU readback, and license notices.
7. **Upload validation:** Run SDK Builder validations, Build & Test, and only then Build & Publish. Preserve the last known good generated shader/material when validation fails. VRChat exposes build callbacks and public builder methods, including Build & Test and Build & Upload; NXSG may hook validation/build preparation without reflecting SDK internals. ([public SDK API](https://creators.vrchat.com/sdk/public-sdk-api/), [build callbacks](https://creators.vrchat.com/sdk/build-pipeline-callbacks-and-interfaces/))

## Blockers and unresolved spikes

The main blockers are live Linux editor/client validation and exact dependency fixtures. No source reviewed here proves that an arbitrary NXSG-generated custom shader will be accepted on every current PC client configuration, and no documentation turns Android/iOS shader compilation into avatar policy approval. Record the Linux editor renderer (OpenGL or Vulkan) for Linux evidence; it does not prove native Windows DX11 behavior. VRChat through Proton is an optional path to establish and test, not an assumed installation or equivalent to native Windows. Fur shells, transparency, mirror cost, shadow behavior, and AudioLink property/version compatibility need matched visual and performance tests before they become default nodes.
