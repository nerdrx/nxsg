# NXSG custom canvas on Unity 2022.3

**Research date:** 2026-09-17. **Target:** Unity **2022.3.22f1**, VRChat’s current creator baseline. This note evaluates editor-canvas choices only; it does not implement a graph UI. “Verified” means stated by Unity’s 2022.3 documentation. “Recommendation” is an NXSG choice. “Spike” requires a pinned-editor smoke test.

## Decision in brief

Unity’s experimental graph editor is not a necessary foundation for NXSG. A retained UI Toolkit canvas is technically viable in 2022.3: `VisualElement` supplies the visual tree and event routing; `generateVisualContent` receives a `MeshGenerationContext`; `Painter2D` can stroke cubic Bezier paths; and the mesh API can be a deterministic fallback. Use ordinary child `VisualElement`s for nodes, ports, selection handles, and accessibility-facing labels, with a dedicated drawing layer for connections and preview overlays.

**Recommendation.** Make the custom canvas a first-class implementation direction. Run a side-by-side S03 spike in the pinned Unity 2022.3.22f1 editor before committing the final surface. Keep `UnityEditor.Experimental.GraphView` as an optional accelerator for comparison or a short-lived prototype, never as a required product dependency. Retain a small IMGUI fallback only for diagnostics or emergency editor compatibility.

The exact patch matters. Unity publishes 2022.3.22f1 as a concrete Editor release with its own package changes and known issues, while the versioned API pages are generally 2022.3-wide. API page presence therefore does not prove that a package behaves identically on 22f1. The smoke fixture must run on 2022.3.22f1 and record Editor log, package lock, API availability, and interaction results. ([Unity 2022.3.22f1 release notes](https://unity.com/releases/editor/whats-new/2022.3.22f1), [VRChat current Unity version](https://creators.vrchat.com/sdk/upgrade/current-unity-version/))

## What a custom retained canvas can use

**Rendering.** Unity documents `VisualElement.generateVisualContent` as an `Action<MeshGenerationContext>` used to generate custom geometry, called when the element is created or repainted; `MarkDirtyRepaint` requests another repaint. `MeshGenerationContext.Allocate` accepts vertices and indices, so NXSG can draw thick connection strips, selection outlines, minimap marks, and diagnostic overlays without depending on GraphView. `Painter2D` is a 2022.3 `UnityEngine.UIElements` API with path operations and stroke/fill state; use `BezierCurveTo` for normal connections and mesh generation when routing needs explicit tessellation or large graphs. ([generateVisualContent](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.VisualElement-generateVisualContent.html), [MeshGenerationContext](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.MeshGenerationContext.html), [Painter2D](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.Painter2D.html))

**Events and gestures.** UI Toolkit routes pointer, mouse, keyboard, focus, and navigation events through the visual tree. `PointerCaptureHelper` exposes capture and release, which is sufficient for dragging a node or an in-progress port connection after the pointer leaves the original element. UI Toolkit manipulators are state machines intended to separate event logic from controls; NXSG can implement `NodeDragManipulator`, `CanvasPanManipulator`, and `ConnectionDragManipulator` rather than placing all state in one window callback. Scroll-wheel input can change zoom on the canvas root; middle-button or space-drag can pan. ([event handling](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Events-Handling.html), [event reference](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Events-Reference.html), [manipulators](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-manipulators.html), [PointerCaptureHelper](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.PointerCaptureHelper.html))

**Transforms and hit testing.** Keep graph coordinates in the portable model and map them to canvas-local coordinates through a root pan/zoom transform. `WorldToLocal` and `LocalToWorld` are available as `VisualElementExtensions`; Unity warns that valid panel/layout state is required, so conversion must happen after attachment and layout. Node and port elements can own rectangular hit targets; connection selection must use a spatial index or distance-to-Bezier test in graph coordinates. Canvas repaint is not hit testing: `generateVisualContent` only draws. ([WorldToLocal](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.VisualElementExtensions.WorldToLocal.html), [LocalToWorld](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.VisualElementExtensions.LocalToWorld.html), [VisualElement](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.VisualElement.html))

**Keyboard, editing, and overlays.** Only focused, focusable elements receive keyboard events. Mark the canvas or a selected node focusable, establish a predictable focus order, and handle Delete, arrows, Shift/Alt modifiers, Enter, Escape, and copy/paste explicitly. `Undo.RegisterCompleteObjectUndo` records Unity object state, so bridge graph snapshots through a Unity edit-session object; undo must remain independent of generated shader assets. `GUIUtility.systemCopyBuffer` is available for text clipboard exchange; serialize copied subgraphs with schema/version/node IDs, reject malformed data, and preserve missing-pack nodes as inert placeholders. Visual overlays can be ordinary elements above the draw layer: search, validation badges, minimap, temporary connection wire, previews, and error callouts. ([keyboard events](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Keyboard-Events.html), [focus order](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.Focusable-tabIndex.html), [Undo.RegisterCompleteObjectUndo](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Undo.RegisterCompleteObjectUndo.html), [GUIUtility.systemCopyBuffer](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/GUIUtility-systemCopyBuffer.html))

Accessibility is partly an NXSG responsibility. 2022.3 exposes focusability, `tabIndex`, labels/tooltips, keyboard and navigation events, but this research found no Unity 2022.3 promise of screen-reader semantics for an arbitrary custom canvas. Do not call keyboard reachability “accessible” without testing the actual Editor and assistive technology. Give every node and port a text name, expose selection and connection actions through menus or inspector controls, and keep the graph model operable without relying on color or tiny hit targets. ([UI Toolkit Focusable API](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/UIElements.Focusable.html), [focus events](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Focus-Events.html))

## Bounded comparison

| Surface | What Unity 2022.3 provides | NXSG cost and risk | Position |
|---|---|---|---|
| **Custom UI Toolkit canvas** | Retained `VisualElement` tree, event propagation/capture, transforms, custom mesh/vector drawing, focus and overlays. | NXSG owns pan/zoom math, port compatibility, routing, spatial hit tests, selection, clipboard, persistence, and performance policy. Two render paths (nodes plus connection layer) must stay synchronized. | **Preferred.** Costs are explicit and testable; model stays independent of Unity internals. |
| **Experimental.GraphView** | `GraphView` already exposes nodes, ports, edges, selection, framing, view transform, compatible-port queries, serialization hooks, and zoom. | Unity labels the API experimental and says it may change or be removed. NXSG inherits its lifecycle, styling, hit-test, serialization, and performance behavior; custom UX still requires wrappers and workarounds. | **Optional accelerator.** Useful for S03 comparison, not a stable contract. ([GraphView](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Experimental.GraphView.GraphView.html), [Node](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Experimental.GraphView.Node.html), [Port](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Experimental.GraphView.Port.html)) |
| **IMGUI fallback** | `EditorWindow.OnGUI` and immediate controls are widely available; quick diagnostics and tiny tools are straightforward. | Every repaint rebuilds the interaction surface. NXSG must manage hot control, keyboard focus, drag state, zoom transforms, clipping, hit tests, and retained graph state itself; dense node layouts become maintenance-heavy. | **Fallback only.** Keep a minimal diagnostic view, not the primary authoring canvas. Unity recommends UI Toolkit for modern, flexible, scalable Editor extensions. ([Extending the Editor](https://docs.unity3d.com/2022.3/Documentation/Manual/ExtendingTheEditor.html)) |

The custom surface's maintenance burden is interaction correctness and performance as node and edge counts grow, especially edge routing, selection semantics, and minimizing VisualElement churn. The 200-node fixture is a proposed test case, not an established performance threshold. GraphView supplies some of that behavior but retains an experimental API boundary. Both candidates can keep authoritative state outside their rendering objects and share the portable graph with future viewers.

## S03 side-by-side spike and acceptance fixture

Run both candidates in separate Editor-only assemblies against the same graph model, on Unity 2022.3.22f1 with the project’s pinned packages. Do not choose from API browsing or a Unity 6 prototype. The fixture must contain **20 nodes** and **200 nodes**, typed ports, parallel edges, a cycle diagnostic, a selected subgraph, long labels, collapsed nodes, and a missing-node placeholder.

The initial comparison is deliberately small: pan/zoom, single/multiple selection and dragging, compatible-port connection, edge hit testing, keyboard reachability, and reload of the shared fixture. Measure code owned and interactions before choosing; do not build two finished editors. After selection, the production S03 acceptance checks are:

1. Open, reload, and re-open the graph with stable node IDs, positions, zoom, selection, and connection order.
2. Pan, wheel-zoom, frame selection/all, drag one node, drag a multi-selection, box-select, connect compatible ports, reject incompatible ports, disconnect, and select an edge by hit test at multiple zoom levels.
3. Perform keyboard focus, Delete, arrows, modifiers, Enter/Escape, undo/redo, copy/paste, duplicate, align/distribute, and search-to-add without losing focus or corrupting the model.
4. Show a temporary connection wire, validation badges, node preview, minimap, and a text-equivalent error path; check repaint and input latency qualitatively and record Editor logs and profiler observations.
5. Reimport/reload after a failed edit and prove last-good graph data survives; capture screenshots plus serialized graph hashes and test results.

**Pass rule:** no unhandled exceptions; all gestures preserve graph invariants; 200-node interaction remains usable; reload preserves state; keyboard and text paths work; no API calls are missing on 22f1. If custom canvas passes and GraphView does not materially beat it on measured gesture correctness or maintenance surface, select custom canvas. If both fail, reduce scope to 20-node MVP and record the unresolved spike rather than introducing a new Unity version.

## Unresolved before implementation

The pinned Editor smoke must confirm `Painter2D.BezierCurveTo`, mesh allocation, pointer capture, `tabIndex`, clipboard, and Undo behavior on the actual 22f1 package set. It must also measure whether one drawing layer plus 200 retained node elements remains responsive on the supported creator machine. Screen-reader behavior, high-DPI rendering, IMGUI/UIToolkit focus handoff, and GraphView serialization quirks remain empirical questions. No Unity 6 Graph Toolkit API or package is part of this recommendation.
